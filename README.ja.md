# Translation LSP

[English](README.md)

ZedでRust、JavaScript／JSX、TypeScript／TSX、C#、C、C++、Pythonのコメント、Pythonのドキュメンテーション文字列、選択したMarkdownなどの文章を翻訳します。訳文はホバー表示（テキスト上で開く情報表示）で読めます。原文はエディタに残ります。コードのコメントにマウスポインターを重ねると、初回から翻訳が始まります。ChatGPTが利用可能な状態では、Markdownの文章を選択して安定させるとバックグラウンドで翻訳し、その範囲のホバーで訳文を読めます。

ChatGPTを使う場合は、本人のChatGPTアカウントで接続し、ChatGPTプランの利用を許可します。設定なしでは、同梱サンプルだけを日本語に訳す模擬モードで動作し、文章を外部へ送りません。

## 導入

開発・利用の対象は **Windows・macOS・Linux** です。Zedと、[rustup経由のRust](https://www.rust-lang.org/tools/install)（1.97以降）を導入してください。ネイティブ依存のビルドにはC/C++の開発環境も必要です。

| OS | ビルドの前提 | ネイティブ実行ファイル |
| --- | --- | --- |
| Windows | MSVC版Rust、Visual Studio Build Toolsの「C++によるデスクトップ開発」とWindows SDK。x86-64ではNASMも導入し、Visual Studioの開発者用PowerShellまたはコマンドプロンプトを使います。 | `target/release/translation-lsp.exe` |
| macOS | Xcode Command Line Tools（`xcode-select --install`）。 | `target/release/translation-lsp` |
| Linux | GCCまたはClangとC/C++開発ツール。Debian/Ubuntuでは `build-essential` と `ca-certificates` を導入します。 | `target/release/translation-lsp` |

Tree-sitterとTLSプロバイダーはネイティブコードをビルドします。別のツールチェーン構成はTLSプロバイダーの[Windows向け要件](https://aws.github.io/aws-lc-rs/requirements/windows.html)と[Linux向け要件](https://aws.github.io/aws-lc-rs/requirements/linux.html)を参照してください。

リポジトリのルートで次のコマンドを実行します。PowerShell・コマンドプロンプト・Bash・Zshで共通です。

```sh
cargo build -p translation-lsp --release --locked
rustup target add wasm32-wasip2
cargo build -p translation-lsp-extension --target wasm32-wasip2 --release --locked
```

Zedの拡張画面で `Install Dev Extension` を選び、リポジトリ内の **`crates/zed-extension`** を指定します。[Zedの開発用拡張の導入手順](https://zed.dev/docs/extensions/developing-extensions)も参照してください。

C#ファイルでは、Zedの[C#言語拡張](https://github.com/zed-extensions/csharp)を導入してください。設定上の言語名は `CSharp` です。`languages.CSharp.language_servers` を明示している場合は、既存のC#サーバーに `"translation-lsp"` を追加します。RoslynやOmniSharpを置き換える必要はありません。

CとC++はZedに組み込まれています。言語サーバーを明示設定している場合は、`languages.C.language_servers` と `languages."C++".language_servers` の既存clangdに `"translation-lsp"` を追加します。

PythonもZedに組み込まれています。`languages.Python.language_servers` を明示設定している場合は、既存のPythonサーバーに `"translation-lsp"` を追加します。

## 設定

拡張ID・言語サーバーの設定キー・ネイティブ実行ファイル名は `translation-lsp` です。

既存のZed設定の `lsp` に次の項目を追加し、`binary.path` をビルドした実行ファイルの絶対パスへ置き換えます。モデルは、接続するアカウントで使えるものを指定してください。下記のモデルと推論強度は設定例です。

```json
{
  "lsp": {
    "translation-lsp": {
      "binary": {
        "path": "REPLACE_WITH_ABSOLUTE_SERVER_PATH",
        "arguments": []
      },
      "initialization_options": {
        "target_language": "ja",
        "source_language": "auto",
        "hover_timeout_ms": 20000,
        "selection_timeout_ms": 30000,
        "document_timeout_ms": 180000,
        "markdown_auto_translate": true,
        "selection_debounce_ms": 450,
        "translation_limits": {
          "input_kib": {
            "hover": 16,
            "document": 1024
          },
          "output_kib": 4096
        },
        "provider": {
          "name": "chatgpt",
          "model": "gpt-6.1-sol",
          "reasoning_effort": "low"
        }
      }
    }
  }
}
```

`binary.path` は言語サーバーを動かすOSの絶対パスにします。Windowsでは `.exe` まで指定してください。

| OS | `binary.path` の例 |
| --- | --- |
| Windows | `C:/Users/you/src/translation-lsp/target/release/translation-lsp.exe` |
| macOS | `/Users/you/src/translation-lsp/target/release/translation-lsp` |
| Linux | `/home/you/src/translation-lsp/target/release/translation-lsp` |

WindowsのパスもJSON内では `/` で区切れます。バックスラッシュを使う場合は1文字ごとに `\\` と記述してください。空白を含むパスでも、値の中にシェル用の引用符を追加しません。

画面上の表示は `target_language` にかかわらず英語です。`target_language` の既定値は `ja`、`source_language` は `auto` です。`auto` では、翻訳する同じ要求の中で原語を判定します。`provider.model` はChatGPTを使う場合に必須です。`reasoning_effort` は省略でき、指定する場合は `none`、`minimal`、`low`、`medium`、`high`、`xhigh`、`max` のいずれかです。モデルや推論強度がアカウントで使えない場合はエラーを返します。設定を変更したら言語サーバーを再起動してください。設定変更は、実行中のサーバーには反映されません。[Zedの言語サーバー設定](https://zed.dev/docs/configuring-languages#configuring-language-servers)に従います。

翻訳のタイミング設定は省略できます。

| 設定 | 既定値 | 指定できる値 | 動作 |
| --- | --- | --- | --- |
| `hover_timeout_ms` | `20000` | 整数 `1000`〜`120000`、両端を含む | ホバー要求ごとの受信時からの応答期限。キュー待ちを含む。 |
| `selection_timeout_ms` | `30000` | 整数 `1000`〜`120000`、両端を含む | 保持した手動選択・Markdownバックグラウンド翻訳の実行期限。ワーカー（翻訳処理を実行するタスク）へ渡した時点から計る。 |
| `document_timeout_ms` | `180000` | 整数 `1000`〜`600000`、両端を含む | 別タブに開く文書・選択範囲の実行期限。ワーカーへ渡した時点から計り、キュー待ちは別。 |
| `markdown_auto_translate` | `true` | 真偽値 | 安定したMarkdownの文章選択からバックグラウンド翻訳を始める。`false` でも手動選択翻訳とコメントのホバーを使える。 |
| `selection_debounce_ms` | `450` | 整数 `100`〜`2000`、両端を含む | ネイティブサーバーが新しい選択を観測してから待つ時間。Zed側の観測待ちは別に加わる。 |

翻訳量の上限は `initialization_options.translation_limits` にまとめます。値は正の整数で、単位はKiB（1 KiB = UTF-8の1024バイト）です。文字数やトークン数ではありません。各階層のオブジェクトや項目を省略すると、その項目の既定値を補います。

| `translation_limits` 内の設定 | 既定値 | 対象 |
| --- | --- | --- |
| `input_kib.hover` | `16` | 新たに開始するコメントのホバー、Markdownバックグラウンド翻訳、手動選択のホバープレビュー。 |
| `input_kib.document` | `1024` | 別タブに開く全文・選択範囲の翻訳。 |
| `output_kib` | `4096` | 表示先によらず、完成した訳文。 |

例えば `"translation_limits": {"input_kib": {"document": 2048}}` とすると、文書入力の上限だけを2 MiBに変更します。ゼロ・負数・小数・null・未知の項目・数値以外は設定エラーになります。サーバーの実行環境で表現できない大きさも拒否します。変更後は言語サーバーを再起動してください。明示実行で入力上限を超えると、実際のサイズ・上限・設定名を表示します。上限を超える自動選択は翻訳を開始しません。既に翻訳済みのキャッシュは、新しい翻訳要求を送らずに閲覧できます。

受付とキャッシュの上限も `translation_limits` の中で調整できます。

```json
"translation_limits": {
  "work": { "admitted": 8, "concurrent": 2, "documents": 1, "automatic": 3, "hover_waiters": 16 },
  "cache": { "entries": 64, "capacity_kib": 16384 }
}
```

`admitted` は実行・待機の合計で、取り消しを指示したワーカーも終了通知までは数えます。`concurrent` は全翻訳の同時実行数、`documents` はタブ翻訳として実行枠を割り当てる同時処理数、`automatic` は手動・タブ翻訳の依頼がなく、コメントのホバーや自動選択によって保持する処理数、`hover_waiters` は個々のホバー応答待ちの上限です。件数は正の整数とし、`documents <= concurrent <= admitted` と `automatic < admitted` を満たす必要があります。明示依頼の受付余地を残す制約であり、実行枠を常に空けておくものではありません。同時実行数を増やすと翻訳プロバイダー（翻訳サービスや模擬実装）への同時要求も増えます。

`cache.entries` は成功・失敗・タブ用を合わせたすべての文書の項目数です。`cache.capacity_kib` は保存する文章の合計容量で、プロセス全体のメモリ上限ではありません。1件の最大結果を格納できるよう、実効容量はこの値と `output_kib` の大きい方になります。メタデータ、原文、処理中の入力、一時ファイルはこの文章容量に含めません。既定値は連続して読む用途の出発点であり、翻訳プロバイダーや機器の測定上限ではありません。省略した入れ子の項目は既定値を使い、変更後は言語サーバーを再起動してください。

次の値が**設定できる最大値**です。上記の既定値とは別であり、超過する設定は黙って切り下げず、起動時に拒否します。

| `translation_limits` 内の設定 | 最大値 |
| --- | --- |
| `input_kib.hover` | `1024`（1 MiB） |
| `input_kib.document`、`output_kib` | 各 `16384`（16 MiB） |
| `work.admitted` | `64` |
| `work.concurrent`、`work.documents` | 各 `8` |
| `work.automatic` | `63`、かつ `admitted` 未満 |
| `work.hover_waiters` | `256` |
| `cache.entries` | `4096` |
| `cache.capacity_kib` | `262144`（256 MiB） |

組み合わせにも制限があります。`max(input_kib.hover, input_kib.document) × work.admitted` は `262144` KiB（256 MiB）以下、`output_kib × work.concurrent` は `65536` KiB（64 MiB）以下にします。例えば文書入力16 MiB・受付64件は拒否され、この入力上限では受付16件までです。出力16 MiBなら同時実行は4件までです。現在キューが空でも、設定上の最大負荷を検証します。

これらはサーバー側の資源保護の基準であり、機器の実測限界や翻訳プロバイダーが処理できる量を表すものではありません。入力の合計容量で受付済み原文を制限し、出力はSSEのエスケープや複数の訳文スナップショットを保持する余地を残すため、より小さくしています。入力の個別上限は大きな文書を許容しつつ、自動・選択範囲のホバー用入力を厳しめに制限します。件数の上限は、小さな文章を大量に指定した場合のスケジューラ・キャッシュの走査も制限します。キャッシュ文章は別枠で最大256 MiBです。開いている原文、パーサー、メモリ管理、通信バッファ、一時ファイルなどの費用もあるため、**プロセス全体のメモリ保証値ではありません**。既定値は変更していません。これを超えて利用する場合は、Zedの設定による回避ではなく、サーバーの基準自体の見直しが必要です。

通信側の制限は、JSONのエスケープ・訳文の重複送信・SSEイベントの付加情報を考慮して `output_kib` に連動します。訳文のサイズとは別に通信処理量を制限し、最大量のメモリを先に確保することはありません。設定値を増やしても、モデルの入力・出力上限や翻訳期限は増えません。長文も一つの要求で送信し、自動分割は行いません。失敗・未完了・上限超過の結果を完成訳として表示・保存しません。

同じキャッシュ済み翻訳を再びタブに開く場合は、一時ファイルを再利用してその文書へ移動します。ファイルが削除された場合や保存済みの内容が変更された場合は、既存の内容を上書きせず新しいプレビューを作ります。新しく翻訳した結果は別ファイルになります。一時プレビューはサーバー終了時に削除し、「別名で保存」で保存したコピーは残します。

別タブに開く翻訳は、コマンドを受け付けた後も処理を続け、完了時に結果を開きます。全文・選択範囲とも、キュー待ちとは別に既定3分の実行期限があります。文字数による自動延長はしません。範囲単位・全件を取り消すコードアクションで止められます。元の文書を編集・閉じた場合も結果を開きません。

未知の項目、型の違う値、範囲外の数値は、英語の設定エラーを返して言語サーバーの起動を止めます。項目を省略すると既定値を使います。

`binary.path` を省略すると、作業ツリーのPATHにある `translation-lsp` を探します。対応言語の `language_servers` を明示している場合は、既存の配列へ `"translation-lsp"` を追加してください。Zedでは `.jsx` も `JavaScript`、`.tsx` は `TSX` の設定を使います。

## 翻訳モデルを変更する

1. Zedのコマンドパレットで `zed: open settings file` を実行します。
2. `lsp.translation-lsp.initialization_options.provider.model` を、使いたいモデルの識別名に変更します。
3. 必要に応じて `lsp.translation-lsp.initialization_options.provider.reasoning_effort` を指定します。APIの既定値を使う場合は省略し、指定する場合は上記の値から選んでください。明示した `none` は省略とは異なります。
4. 設定を保存します。この拡張を使う文書で、コマンドパレットから `editor: restart language server` を実行します。

拡張は設定したモデルの識別名をそのまま翻訳APIへ送り、別のモデルへ自動で切り替えません。そのモデルと推論強度をアカウントで使えるかどうかは、APIが判断します。

翻訳には通常のテキスト出力を使います。ChatGPTアカウントで利用可能なモデルを選んでください。要求が失敗しても、拡張が別モデルへ切り替えることはありません。

## ChatGPTへ接続する

対応する文書でZedのコマンドパレットから `editor: toggle code actions` を実行し、`ChatGPT account…` から `Continue with ChatGPT / Choose account` を実行します。アカウントの選択肢から新規追加または保存済みの登録を選び、ブラウザで認証と利用許可を完了してください。設定の読み込み、アカウント管理メニューを開く操作、ホバーだけでは認証を開始しません。利用可能になると接続項目は `Change ChatGPT account` に変わり、利用許可の項目は表示されません。サインアウトはサインイン中だけ表示されます。管理操作中は重複操作の候補を表示しません。接続状態を読み取れない場合は `Check ChatGPT connection…` を実行し、表示された案内を確認してください。

- `Enable ChatGPT plan use` は、サインイン済みでプラン利用が許可されていない場合に使います。
- `ChatGPT Usage` は、[ChatGPTの使用量設定](https://chatgpt.com/settings/usage)を開きます。利用枠やクレジットの許可はこの設定に従います。
- `Sign out of ChatGPT` は、現在の登録のセッション終了を試み、その登録の認証情報を削除します。別の登録は残ります。通信のため終了を確認できなかった場合は案内に従ってChatGPT設定からアプリを切断できます。

認証情報は、OSごとに次のローカル設定ディレクトリへ保存します。

| OS | 認証情報の保存先 |
| --- | --- |
| Windows | `%LOCALAPPDATA%\translation-lsp\` |
| macOS | `~/Library/Application Support/translation-lsp/` |
| Linux | `$XDG_CONFIG_HOME/translation-lsp/`。未設定の場合は `~/.config/translation-lsp/` |

保存先は `dirs::config_local_dir()` を通じてOSから取得します。同じメールアドレスでも登録ごとのUUIDで区別し、再認証には元の登録を使います。APIキーの設定や、別の課金経路への自動切替はありません。接続方式は[公式のSign in with ChatGPT](https://developers.openai.com/siwc/token-sharing-open-source/sign-in)に基づきます。

認証データは `auth.json` のバージョン2で保存します。バージョン1は初回アクセス時に認証ストアをロックし、原子的に保存して移行します。認証情報のバックアップは作りません。トークン・登録・選択中のアカウントは保持します。登録ごとに認可IDを追加し、トークン更新では保持、再認証では更新します。トークン更新や一時的なストアのロックでキャッシュ済みの訳は破棄せず、表示前に認可を再確認します。

旧版のバイナリはバージョン2を読めません。旧版へ戻す場合は、その時点の認証データをバージョン1へ変換するか、再認証してください。

## 翻訳を表示する

対応するコードのコメントにマウスポインターを重ねるか、カーソルを置いてZedの `editor: hover` を実行します。同じ種類・字下げの隣接した行コメントはまとめて訳し、空行やコードを挟むと分けます。ブロックコメントは一つずつ扱います。コメント記号と直後のASCIIスペース一つを除いた本文を翻訳します。

既定では、すべての文書を合わせて最大2件を同時に実行し、実行・待機の合計8件を受け付けます。同じ文書の複数範囲を続けて指定できます。同じ対象への要求は一つの処理を共有します。タブ翻訳の開始は最大1件とし、範囲翻訳が進められる枠を残します。受付順で実行しますが、タブ用の枠を待つ処理だけは後続の範囲翻訳が追い越せます。実行中の範囲に同じ対象のタブ表示を追加する場合は処理を共有し、追加の実行枠を使いません。上限は `translation_limits.work` で変更できます。

選択・タブ翻訳コマンドは受付時に応答します。選択の変更・解除、別タブへの移動、エディタによるコマンド応答待ちの取り消しでは、受付済みの処理を取り消しません。個々のホバー応答を取り消したり、その応答待ちが時間切れになったりしても、受付済みのコメント翻訳は継続します。コメントAからBへ移ってもAの実行・待機は残り、あとで各コメントに戻って完成訳を読めます。そのため、通りすがりでもZedがホバー要求を送って受付された場合は、翻訳の利用量を消費します。原文の文書内を編集する・文書を閉じる・認可を変更する・サーバーを終了する場合は、関連する処理とキャッシュを無効にします。トークン更新では無効にしません。`ChatGPT account…` を開いて閉じるだけなら翻訳を継続します。

1件を止めるには、その範囲にカーソルか選択範囲を置き、コードアクションの `Cancel translation of lines …` を実行します。`Cancel all translations` はアカウントメニューを残してすべての翻訳を取り消します。以前の取り消しアクションを再実行しても、同じ範囲の新しい依頼には影響しません。クライアントが進捗の取り消し操作を表示すれば、それでも全件を取り消せます。Zedの進捗操作とアクション一覧の更新は実機確認が必要で、主にコードアクションから取り消します。

自動選択が直前の選択と重なり、安定待ちを終えた場合は、直前の処理の自動保持だけを置き換えます。途中の空の選択や翻訳対象外の選択では調整の連続性を切らず、別文書か、重ならない翻訳対象の選択を観測すると切ります。明示依頼や別のホバーが共有する処理は残ります。コメントのホバーと自動選択を合わせた自動保持の既定上限は3件です。満杯で拒否されたコメントのホバーは保持しません。枠が空いた後に戻るか、選択して手動翻訳してください。自動選択では、満杯の間は最新の未受付候補だけを保持するため、D、Eと選択するとDは翻訳されない場合があります。候補は `selection not yet accepted` と表示し、受付済みの待機件数へ加えません。明示操作が満杯で拒否された場合は、受け付けなかったことを通知します。

ホバーは、その位置を含む完成訳のうち最も新しい依頼の結果を優先します。新しい処理や失敗によって、読める完成訳を隠しません。完成訳がなければ処理中の範囲に合流し、失敗済みなら範囲ごとのエラーと手動再試行の案内を表示します。選択を解除した後やコード内の手動選択でも、以前の依頼を見つけられます。明示操作の完了・失敗通知にはファイル名と行番号を付けます。自動翻訳の完了ポップアップは出しません。失敗範囲内にカーソルを置き、Code Actionsから `Retry translation of lines …` を選ぶと、文章を選び直さずに記録された範囲を再試行できます。利用上限で停止した後も、明示的な再試行として扱います。ホバーだけでは失敗表示を維持します。翻訳と無関係な種別に限定されたCode Action要求では、自動翻訳の選択状態を変更しません。

翻訳の待機・実行中は、ステータスバー左側にスピナー（回転する処理中の印）と文字を直接表示します。`Queued: …` は待機中の件数、`Translating: …, queued: …` は実行中と待機中の件数です。同じ範囲への複数の要求は一件と数えます。この欄はほかの言語サーバーと共有するため、別の活動が優先されることがあります。

スピナーは取り消しや時間切れを含め、作業が終わると消えます。結果は原文へのホバーで確認してください。状態表示に対応するクライアントでは、翻訳失敗・時間切れの警告が残り、再試行・編集・文書の閉鎖で消えます。これらの表示に対応しない場合も、ホバーと明示操作の通知を使えます。

ChatGPTが利用可能で `markdown_auto_translate` が `true` の場合、Markdownの文章を選択して安定させるとバックグラウンドで翻訳します。既定ではZedから選択が届いた後に450ms待ち、Zed側の観測待ちも別に加わります。その範囲でホバーを開いて訳文を読みます。バックグラウンド翻訳の完了通知は表示しません。コードやリンク先だけ・空白だけの選択では開始しません。コードの囲みなどを途中で切り、選択部分だけでは構文の解釈が変わる範囲も自動対象外です。囲みを含めて選び直すか、手動翻訳を使ってください。選択した文章はコピー目的の場合も送信され得ます。

すぐに実行したい場合やバックグラウンド翻訳が失敗した場合は、コードアクションの `Translate selection to …` を使います。明示実行では完了通知 `Translation ready. Hover over the selected text to view it.` が出ます。コード言語やMarkdown以外でも範囲選択による翻訳を使えます。未接続またはプラン利用が無効の場合は、`ChatGPT account…` から接続・利用許可を実行してください。選択がないとホバー用の翻訳項目は表示されません。

Markdownまたはプレーンテキスト（Zedの言語名は `Plain Text`）では、`Translate selection to … and open in tab` で訳文を別タブに開けます。選択がない場合は `Translate document to … and open in tab` となり、文書全体を翻訳します。どちらも `translation_limits.input_kib.document` の上限を使い、既定は1 MiBです。クライアントには `window/showDocument` 対応が必要です。

Markdownの訳文は一時的な `.md` ファイルとして開きます。コマンドパレットの `markdown: open preview` で整形された表示にし、必要に応じてソースタブへ戻れます。プレーンテキストの訳文は `.txt` で開きます。通常のMarkdownの開き方は変更しません。開いた訳文はその時点の内容で、原文の編集には追従しません。必要なときに再び翻訳操作を実行してください。

残したい訳文は、言語サーバーの再起動やZedの終了前に「別名で保存」してください。一時ファイルはサーバーの正常終了時に削除します。異常終了した場合はシステムの一時フォルダーに残ることがあります。別名保存したファイルは削除しません。

相対パスのリンクや画像は一時ファイルの位置を基準に解決します。元の相対パスを使う場合は、原文と同じフォルダーへ別名保存してください。

明示した翻訳や管理操作が失敗した場合は、エラー通知を確認してください。認証更新で `invalid_grant` などが返された場合は、`ChatGPT account…` → `Continue with ChatGPT / Choose account` から保存済みの登録を選び、再接続します。

完成した訳文をテキストとしてそのまま表示します。選択した文章をまとまりとして渡し、意味、コード、識別子、URLを保って訳文だけを返すようモデルに指示します。訳文をJSONの断片へ分けたり、Markdownの書式や改行の違いを理由に拒否したりしません。この指示によって翻訳の正確さを保証するものではありません。

手動の選択翻訳・全文翻訳は、字下げやコードだけの内容でも指定した文章を送信します。コードや識別子の保持はモデルに指示します。Markdownの散文判定はバックグラウンドでの自動翻訳だけに適用し、翻訳プロバイダーへ送らずに原文を翻訳成功として表示することはありません。

ChatGPTへ送る文章は、抽出したコメント本文、選択範囲、または文書翻訳を明示した場合の文書全体です。会話履歴は送りません。訳文を原文へ書き戻すこともありません。

複数範囲の訳をメモリに保持し、`translation_limits.cache` でサーバー全体の件数・容量を制限します。完了順が逆でも、位置を含む完成訳のうち依頼が最も新しいものを表示します。新しい訳が成功した時点で、その範囲に完全に含まれる古い訳を除きます。上限に達すると、長く使われていない項目から外します。タブ用の結果はホバー用と分け、元文書ごとに成功結果を最大1件保持し、同じ全体予算に含めます。明示的な翻訳依頼で、その表示先にキャッシュがない場合は、もう一方の表示先にある完全に同じ範囲の完成訳を再利用します。依頼した操作の入力上限は引き続き適用します。タブに開くだけではホバー表示は増えず、同じ範囲をホバー用に明示的に翻訳した場合に再利用します。再試行アクションは完成訳を再利用せず、新しく翻訳するか、すでに処理中の翻訳に合流します。同じキャッシュ済みのタブ結果を再度開く場合は、一時ファイルが削除されたり保存済みの内容が変更されたりしていなければ再利用します。

キャッシュから外れたMarkdownの範囲は、ホバーだけでは再翻訳しません。選択するか手動実行してください。コメントはホバーで再翻訳できます。原文の編集・閉鎖・アカウント変更・再認証で関連項目を破棄します。ホバーでは文章をディスクに保存せず、タブ表示では完成訳を一時ファイルへ書き込みます。失敗・途中切断・取り消し・期限切れの部分訳は公開しません。保持した範囲の失敗は訳文としてではなく、エラーとして表示します。

## 模擬モード

`provider` を省略するか `{"name":"mock"}` にすると、接続せずに同梱サンプルを試せます。[samples/comment.rs](samples/comment.rs) のコメント、または [samples/comment.cs](samples/comment.cs) の通常コメント・XMLドキュメントコメントにマウスポインターを重ねてください。C/C++は [samples/comment.c](samples/comment.c) と [samples/comment.cpp](samples/comment.cpp) でDoxygenコメントも試せます。

Pythonのコメントとドキュメンテーション文字列は [samples/comment.py](samples/comment.py) で試せます。[samples/paragraph.md](samples/paragraph.md) では段落を選択し、コードアクションの `Translate selection to ja` を実行してから、選択範囲にマウスポインターを重ねます。模擬モードのMarkdownは手動実行が必要です。

模擬モードはこれらのサンプルと改行の違いだけに対応します。ほかの本文や日本語以外の訳先ではエラーを返します。ホバーには `Mock translation (fixed sample)` と表示します。

## 制約

- ホバーによる自動翻訳はRust、JavaScript／JSX、TypeScript／TSX、C#、C、C++、Pythonのコメントとドキュメンテーション文字列が対象です。Markdownは文章の選択後にバックグラウンド翻訳し、段落へのホバーだけでは開始しません。
- 選択変更はZedからの範囲要求で観測します。一つのサーバーが最新の候補と調整の連続性を扱い、複数エディタの選択を独立には追跡しません。受付済みの異なる範囲は保持します。コピー目的の文章選択でも自動翻訳が始まる場合があります。バックグラウンド翻訳の失敗から新しい処理を自動送信し直すことはありません。
- C#は `//`、`/* ... */`、`///`、`/** ... */` に対応します。同じ種類・字下げで連続する行コメントはまとめて翻訳します。XMLドキュメントコメントはタグ付きの訳文をホバーに表示し、タグ・属性の保持をモデルへ指示します。XML専用の整形表示や構造検証は行いません。構文エラーで判定が曖昧な範囲のコメントはホバーによる自動翻訳の対象から外れますが、手動の範囲選択翻訳は使えます。
- C/C++は通常コメントとDoxygen形式（`///`、`//!`、`/**`、`/*!`、末尾の説明用の `<` 付き形式）に対応します。`@param`などは本文に残し、コマンドと引数名の保持をモデルへ指示します。構文エラー範囲を飛ばし、マクロや入力途中の式より後でも認識できたコメントを抽出します。ただし、エラー範囲に引用符やブロックコメントの開始記号がある場合は、未閉鎖の内容をコメントと誤認しないようそこで停止します。曖昧な範囲は手動選択で翻訳できます。
- Pythonは `#` コメントと、モジュール・クラス・関数の先頭のドキュメンテーション文字列に対応します。通常の文字列・raw文字列・Unicode文字列、括弧付き、暗黙に連結した文字列を扱います。代入された文字列、f文字列（f-string）、バイト列リテラルは自動翻訳しません。ドキュメンテーション文字列の引用符と接頭辞を除き、エスケープや字下げはPythonとして評価せず原文のまま送ります。シバン（スクリプト先頭の `#!` 行）は除外します。構文エラー範囲を飛ばして抽出を続けます。ただし、エラー範囲に引用符がある場合は、未閉鎖文字列内の内容をコメントと誤認しないようそこで停止します。手動選択は使えます。
- 未閉鎖のブロックコメントは、閉じるまで自動翻訳を待ちます。JS／TSの解析が致命的な構文エラーで停止した場合、その後のコメントは自動で取得できません。範囲選択による翻訳を使うか、構文を修正してください。
- 入力の既定上限はホバーが16 KiB、文書が1 MiB、出力は4 MiBです。ホバー応答は受信から既定20秒で、キュー待ちを含みます。手動・自動選択の範囲翻訳は既定30秒、タブ翻訳は180秒の実行期限をワーカーへの引き渡し時に設定します。保持したコメント翻訳は `hover_timeout_ms` を使い、引き渡しから既定20秒の実行上限を設けます。ホバー応答の待ち期限とは独立しています。合流では実行時間をリセットせず、長い用途が加わった場合だけ元の開始時刻から上限を延ばします。API呼び出し・認証更新・再試行・ストリーミング受信は実行期限に含みます。保持した処理のキュー待ちは別で、先行する処理数は受付・同時実行の上限で制限します。OAuth・管理操作には別の内部制限があります。
- HTTP 200の後に通知される過負荷を含め、明示された一時的なサービスエラーは元の期限内で最大一度だけ再試行します。既定の待機は2秒です。数値の `Retry-After` が120秒以内ならその秒数を使い、それ以外の値では手動再試行に委ねます。取り消し・文書の変更・アカウントの変更で再試行待ちも停止します。接続失敗や途中切断は自動で再送しません。
- 利用枠の上限・アカウントの制限・設定エラーでは自動翻訳を停止します。原因を解消したら、選択範囲または文書の翻訳を明示実行すると再試行できます。再起動や再接続は不要です。明示した再試行が成功するまで自動翻訳の停止は維持します。停止前に受け付けた待機依頼は新たなHTTPを送らず失敗とし、停止通知はまとめ、各範囲の失敗表示を保持します。利用枠はChatGPTの使用量設定で確認してください。認証更新で無効な認可と判明した場合を除き、失敗しても認証情報を保持します。
- ホバーの位置と幅はZedが決めます。上側への固定や、本文を完全に隠さない配置は保証しません。

## 開発

両クレートはRust Edition 2024です。ネイティブ言語サーバーにはRust 1.97以降、WASM拡張にはRust 1.96以降が必要です。古い最低対応Rustの維持より依存更新を優先し、必要に応じて対象クレートの要件を引き上げます。仮想ワークスペースには依存関係リゾルバーのバージョン3を使います。`Cargo.lock` をバージョン管理し、検証とリリースビルドは `--locked` で実行してください。

```sh
cargo fmt --all --check
cargo test --workspace --locked
cargo clippy --workspace --all-targets --locked -- -D warnings
```

[CIワークフロー](.github/workflows/ci.yml)はWindows・macOS・Linuxそれぞれでワークスペース全体のテスト、fmt、Clippy、ネイティブとWASMのリリースビルドを実行します。1 OSでの成功だけを他OSの成功とは扱いません。リリース前には3 OSのCI結果に加え、各OSのZedで拡張導入・ネイティブ起動・認証・コメント翻訳・文書翻訳の表示と保存を確認してください。HTTP/OIDCのテスト用環境は合成の認証情報を使うため、ChatGPTアカウントは不要です。

依存関係のバージョンは `major.minor` のCargo互換範囲で指定します。特定のバージョンに固定する場合は、互換性上の理由を記録してください。更新時は `cargo update` によるロックファイルの差分を確認し、上記の検証とネイティブ・WASM両方のリリースビルドを実行してください。Oxcの関連クレートは同じリリース系列に揃えます。`zed_extension_api` の更新時は、対象ZedのAPI対応も確認してください。

新しいコード言語のコメント抽出には、Tree-sitterの文法を第一候補として検証します。既存のRust用字句解析器とJavaScript／TypeScript用Oxcは継続して使用します。

現在のバージョン固定の例外は `unicode-ident = "=1.0.24"` です。Rustの字句解析器とUnicodeテーブルの版を揃えるために固定しています。字句解析器と関連するUnicodeテーブルが同じ版に対応した時点で、固定を外してまとめて更新してください。
