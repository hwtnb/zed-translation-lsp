# DeepL API

[English](../../providers/deepl.md)

`deepl` プロバイダーを選ぶと、APIキーを使い、DeepL APIを通じて翻訳します。APIキーは、コードアクションの `DeepL API key…` から保存します。DeepL API Freeのキーも、有料のDeepL APIのプランのキーも使えます。

DeepLは翻訳サービスで、言語モデルではないため、指示文を受け付けません。そのため、[送信する内容](#送信する内容)のとおり、送る文章はサーバーが整えます。また、選択した単語は、辞書の項目として引かずに翻訳します。

## 最小の設定

```json
{
  "lsp": {
    "translation-lsp": {
      "initialization_options": {
        "target_language": "ja",
        "provider": {
          "name": "deepl"
        }
      }
    }
  }
}
```

`initialization_options` のほかの設定は、[設定](../configuration.md)のとおりに働きます。APIキーは設定に含めません。[認証](#認証)のとおりに保存してください。

## 設定項目

| 設定 | 既定値 | 規則 |
| --- | --- | --- |
| `provider.name` | なし | `"deepl"` でこのプロバイダーを選びます。 |

このプロバイダーには、ほかの項目はありません。`model` や `document` など、知らない項目は設定エラーです。

このプロバイダーでは、`target_language` は `ja`、`en-US`、`pt-BR`、`zh-Hans` のような言語コードにする必要があります。`source_language` は `auto` か言語コードです。`Japanese` のような言語名は設定エラーです。サーバーは、`JA` や `PT-BR` のように大文字にしたコードを送ります。`source_language` では言語の部分だけを送ります。たとえば `pt-BR` なら `PT` です。`auto` の場合は、DeepLが言語を判別します。ある言語に翻訳できるか、英語の `en-US` と `en-GB` のように地域の指定が要るかは、DeepLが決めます。DeepLが受け付けないコードは、`Value for 'target_lang' not supported.` のようなDeepLのメッセージを添えたエラーになります。DeepLが扱う言語は、DeepLの[対応言語](https://developers.deepl.com/docs/getting-started/supported-languages)のページにあります。

設定を変更したら、言語サーバーを再起動してください。

## 認証

対応する文書でZedのコマンドパレットから `editor: toggle code actions` を実行し、`DeepL API key…` から `Save DeepL API key` を実行します。OSの端末のウィンドウが開き、キーを尋ねます。そこにキーを貼り付けてEnterを押してください。貼り付けた内容は端末に表示されません。保存した旨が表示されたら、Enterを押してZedに戻ります。次の翻訳からそのキーを使い、言語サーバーの再起動は要りません。キーを入れずにEnterを押すと、何も保存しません。

キーは、DeepLのアカウントの[API Keys & Limitsのページ](https://www.deepl.com/your-account/keys)で確認できます。

DeepL API Freeのキー（末尾が `:fx`）は `https://api-free.deepl.com` に、それ以外のキーは `https://api.deepl.com` に送ります。送り先を変える設定はありません。

使えるキーが保存されていない間、サーバーのコードアクションは `DeepL API key…` だけです。保存されている間、メニューは次の項目に変わります。

- `Replace DeepL API key` は、同じ端末を開き、保存済みのキーを別のキーに置き換えます。
- `Remove DeepL API key` は、確認のあと、お使いのコンピューターからキーのファイルを削除し、進行中の翻訳を取り消し、表示済みの訳文を破棄します。キーそのものは、DeepLのアカウントで削除するまで有効です。

キーが保存されている間、メニューはMarkdownとPlain Textの文書に出ます。ほかの文書では、キーが拒否されたときなど、翻訳に失敗した範囲にだけ出ます。それ以外のときにキーを置き換えるか削除するには、MarkdownかPlain Textのファイルを開いてください。

端末の開き方とキーの保存の仕方は、Anthropic APIのキーと同じで、そのページの[認証](anthropic.md#認証)で説明します。`Save DeepL API key` または `Replace DeepL API key` のあとに出る通知には、ウィンドウが開かないときに自分で実行するコマンドが入っています。言語サーバーのパスに `deepl-key` を続けたものです。

キーは、サーバーの認証情報のディレクトリにあるファイル `deepl-api-key` に保存します。ディレクトリとファイルの検査は、Anthropicのキーのファイルと同じです。

| OS | キーのファイル |
| --- | --- |
| Windows | `%LOCALAPPDATA%\translation-lsp\deepl-api-key` |
| macOS | `~/Library/Application Support/translation-lsp/deepl-api-key` |
| Linux | `$XDG_CONFIG_HOME/translation-lsp/deepl-api-key`。未設定の場合は `~/.config/translation-lsp/deepl-api-key` |

キーは、端末からファイルへ渡ります。Zedの設定には書かず、環境変数も、Zedとサーバーの間のメッセージも通りません。

使えるキーがなくてもサーバーは起動し、翻訳を依頼すると、APIへ接続せずに設定エラーを返します。

## 費用と使用量

DeepLは、翻訳した文章の文字数を、キーを発行したアカウントのプランで数えます。DeepL API Freeでは毎月の利用枠から差し引き、有料のプランでは料金がかかります。プランと料金は、DeepLの料金のページにあります。タブに開く翻訳も、ほかの翻訳と同じように送り、数えられます。

コメントのホバーとMarkdownの選択による自動翻訳は、[使い方](../usage.md)のとおり、確認なしに要求を送ります。

`DeepL API key…` のメニューは、キーの保存、置き換え、削除を行います。使用量を開くコマンドはありません。使用量は、DeepLのアカウントの[API Usageのページ](https://www.deepl.com/your-account/usage)で確認できます。

## 送信する内容

翻訳のために送る文章は、[送信する内容](../usage.md#送信する内容)で説明します。DeepLは指示文を受け付けないため、サーバーはその文章を区切って送ります。

- 段落の各行は1つにつなぎます。行をまたいだ文を、1つの文として訳させるためです。段落は、空行、コロンで終わる行で終わり、ドキュメントのタグのように `@` で始まる行の前でも終わります。
- Markdownの見出し、箇条書きの項目（後に続く行を含む）、引用、表のセルは、それぞれ別に送ります。訳文は、`## `、`- `、`> ` など、元の行頭の記号の後ろに戻します。表の見出しの下の行は、そのまま残します。
- `/** … */` の中の選択範囲のように、2行目からあとの各行が字下げと `*` で始まるテキストでは、各行の `*` を残し、箇条書きとして読みません。コメント全体は、この `*` を除いて送ります。
- `` ``` `` などの囲みの中のコードブロックは送らず、そのまま残します。空行と区切り線も同じです。
- バッククォートで囲んだコードと、`http://` や `https://` で始まるURLは、XMLで印を付けて送り、印の部分は訳さないようDeepLに指定します。サーバーは、それぞれの印の位置に元の文字列を戻します。
- コードとURLを除いて文字のない部分は、送りません。

訳した段落は、元が何行でも1行になります。字下げした行はコードとして扱いません。訳したくないコードは、囲みのあるコードブロックか、バッククォートで囲んでください。

要求は `/v2/translate` に、`tag_handling` を `xml`、`ignore_tags` を `x` にして送り、区切った文章をそれぞれ別のテキストとして含めます。DeepLは、それぞれを互いに独立して訳します。1回の要求に入れる文章は96 KiBまでです。それより長い文章は、何回かの要求に分けて順に送り、すべての要求が成功したときにだけ表示します。DeepLが印を失ったり、重ねたり、加えたりした訳文は、表示せずにエラーとして報告します。

## エラーと停止

拒否されたキー（HTTP 403）、使い切った利用枠（HTTP 456）、DeepLが受け付けない言語コードでは、自動翻訳を停止し、HTTPの状態コードとDeepLのメッセージを報告します。別のキーを保存するか、アカウントの使用量を確かめるか、設定を直したあと、選択範囲または文書の翻訳を明示的に実行してください。それが成功すると自動翻訳を再開します。拒否されたキーによる停止は、`DeepL API key…` から別のキーを保存すると終わります。停止は、それが起きたキーに限られるからです。

キーの保存、置き換え、削除に、言語サーバーの再起動は要りません。あるキーで得た訳文と失敗の記録は、別のキーでは表示しません。キーが替わったときに進行中だった翻訳は、完了しても破棄します。設定を変更した場合は、言語サーバーの再起動が必要です。

要求の多すぎ（HTTP 429と529）とサーバーのエラーは、[自動の再試行](../behavior.md#自動の再試行)のとおり一度だけ再試行します。印を失った訳文は再試行せず、自動翻訳も停止しません。

どのプロバイダーにも共通する規則は、[停止](../behavior.md#停止)と[自動の再試行](../behavior.md#自動の再試行)で説明します。

## 保存するデータ

キーは、[認証](#認証)で説明したファイル `deepl-api-key` に、平文で入ります。ChatGPTプロバイダーが認証情報を保存するのと同じディレクトリです。ファイルを書くのは、メニューが端末で動かす `deepl-key` コマンドです。ディレクトリがなければ、このコマンドが作ります。`Remove DeepL API key` は、このファイルだけを削除します。それ以外では、言語サーバーはファイルを読むだけです。

macOSで「ターミナル」を開くとき、サーバーは一時ディレクトリにスクリプトを書きます。スクリプトに入るのは言語サーバーのパスだけで、キーは入りません。「ターミナル」が実行すると、スクリプトは自分を削除します。

サーバーがキーをログ、エラー文、通知、ディスクのほかの場所に書くことはありません。
