# 動作

[English](../behavior.md)

このページでは、言語サーバーが従う規則を説明します。受け付ける処理の量、受付済みの処理が続く条件、自動選択の追跡、ホバーが返す結果、キャッシュ、期限、再試行、停止を扱います。操作の方法は[使い方](usage.md)で説明します。

## 受付と実行枠

既定では、すべての文書を合わせて最大2件を同時に実行し、実行・待機の合計8件を受け付けます。同じ文書の複数範囲を続けて指定できます。同じ対象への要求は一つの処理を共有します。タブ翻訳の開始は最大1件とし、範囲翻訳が進められる枠を残します。受付順で実行しますが、タブ用の枠を待つ処理だけは後続の範囲翻訳が追い越せます。

実行中の範囲に同じ対象のタブ表示を追加する場合は処理を共有し、追加の実行枠を使いません。この共有は `provider.document` を設定していない場合の動作です。設定している場合は、同じ範囲でもタブ翻訳と範囲翻訳を別の処理として扱います。互いに合流せず、それぞれを受付件数に数え、それぞれが実行枠を使います。

上限は `translation_limits.work` で変更できます。

## 受付済みの処理が続く条件

選択・タブ翻訳コマンドは受付時に応答します。選択の変更・解除、別タブへの移動、エディタによるコマンド応答待ちの取り消しでは、受付済みの処理を取り消しません。個々のホバー応答を取り消したり、その応答待ちが時間切れになったりしても、受付済みのコメント翻訳は継続します。コメントAからBへ移ってもAの実行・待機は残り、あとで各コメントに戻って完成訳を読めます。そのため、通りすがりでもZedがホバー要求を送って受付された場合は、翻訳の利用量を消費します。

原文の文書内を編集する・文書を閉じる・認可を変更する・サーバーを終了する場合は、関連する処理とキャッシュを無効にします。トークン更新では無効にしません。Anthropicプロバイダーでは、キーの保存、置き換え、削除が認可の変更に当たります。`ChatGPT account…` や `Anthropic API key…` を開いて閉じるだけなら翻訳を継続します。

## 自動選択

自動選択が直前の選択と重なり、安定待ちを終えた場合は、直前の処理の自動保持だけを置き換えます。途中の空の選択や翻訳対象外の選択では調整の連続性を切らず、別文書か、重ならない翻訳対象の選択を観測すると切ります。明示依頼や別のホバーが共有する処理は残ります。

コメントのホバーと自動選択を合わせた自動保持の既定上限は3件です。満杯で拒否されたコメントのホバーは保持しません。枠が空いた後に戻るか、選択して手動翻訳してください。自動選択では、満杯の間は最新の未受付候補だけを保持するため、D、Eと選択するとDは翻訳されない場合があります。候補は `selection not yet accepted` と表示し、受付済みの待機件数へ加えません。明示操作が満杯で拒否された場合は、ファイル名・行範囲と、受け付けなかったことを通知します。

選択変更はZedからの範囲要求で観測します。一つのサーバーが最新の候補と調整の連続性を扱い、複数エディタの選択を独立には追跡しません。受付済みの異なる範囲は保持します。コピー目的の文章選択でも自動翻訳が始まる場合があります。バックグラウンド翻訳の失敗から新しい処理を自動送信し直すことはありません。

翻訳と無関係な種別に限定されたCode Action要求では、自動翻訳の選択状態を変更しません。

## ホバーが返す結果

ホバーは、その位置を含む完成訳のうち最も新しい依頼の結果を優先します。新しい処理や失敗によって、読める完成訳を隠しません。完成訳がなければ処理中の範囲に合流し、失敗済みなら範囲ごとのエラーと手動再試行の案内を表示します。選択を解除した後やコード内の手動選択でも、以前の依頼を見つけられます。

## キャッシュ

複数範囲の訳をメモリに保持し、`translation_limits.cache` でサーバー全体の件数・容量を制限します。完了順が逆でも、位置を含む完成訳のうち依頼が最も新しいものを表示します。新しい訳が成功した時点で、その範囲に完全に含まれる古い訳を除きます。上限に達すると、長く使われていない項目から外します。

タブ用の結果はホバー用と分け、元文書ごとに成功結果を最大1件保持し、同じ全体予算に含めます。明示的な翻訳依頼で、その表示先にキャッシュがない場合は、もう一方の表示先にある完全に同じ範囲の完成訳を再利用します。依頼した操作の入力上限は引き続き適用します。タブに開くだけではホバー表示は増えず、同じ範囲をホバー用に明示的に翻訳した場合に再利用します。`provider.document` を設定している場合は、もう一方の表示先の結果を再利用せず、それぞれの設定で翻訳します。

再試行アクションは完成訳を再利用せず、新しく翻訳するか、すでに処理中の翻訳に合流します。同じキャッシュ済みのタブ結果を再度開く場合は、一時ファイルが削除されたり保存済みの内容が変更されたりしていなければ再利用します。

キャッシュから外れたMarkdownの範囲は、ホバーだけでは再翻訳しません。選択するか手動実行してください。コメントはホバーで再翻訳できます。原文の編集・閉鎖・アカウント変更・再認証で関連項目を破棄します。ホバーでは文章をディスクに保存せず、タブ表示では完成訳を一時ファイルへ書き込みます。失敗・途中切断・取り消し・期限切れの部分訳は公開しません。保持した範囲の失敗は訳文としてではなく、エラーとして表示します。

## 期限

ホバー応答は受信から既定20秒で、キュー待ちを含みます。手動・自動選択の範囲翻訳は既定30秒、タブ翻訳は180秒の実行期限をワーカーへの引き渡し時に設定します。保持したコメント翻訳は `hover_timeout_ms` を使い、引き渡しから既定20秒の実行上限を設けます。ホバー応答の待ち期限とは独立しています。合流では実行時間をリセットせず、長い用途が加わった場合だけ元の開始時刻から上限を延ばします。API呼び出し・認証更新・再試行・ストリーミング受信は実行期限に含みます。保持した処理のキュー待ちは別で、先行する処理数は受付・同時実行の上限で制限します。OAuth・管理操作には別の内部制限があります。

## 自動の再試行

HTTP 200の後に通知される過負荷を含め、明示された一時的なサービスエラーは元の期限内で最大一度だけ再試行します。既定の待機は2秒です。数値の `Retry-After` が120秒以内ならその秒数を使い、それ以外の値では手動再試行に委ねます。取り消し・文書の変更・アカウントの変更で再試行待ちも停止します。接続失敗や途中切断は自動で再送しません。

## 停止

利用枠の上限・アカウントの制限・設定エラーでは自動翻訳を停止します。原因を解消したら、選択範囲または文書の翻訳を明示実行すると再試行できます。再起動や再接続は不要です。明示した再試行が成功するまで自動翻訳の停止は維持します。停止前に受け付けた待機依頼は新たなHTTPを送らず失敗とし、停止通知はまとめ、各範囲の失敗表示を保持します。Anthropicプロバイダーも、請求・キー・モデル・権限のエラーを同じ規則で扱います。[エラーと停止](providers/anthropic.md#エラーと停止)を参照してください。
